# GENESIS Venue Recovery

![tag:innovationlab](https://img.shields.io/badge/innovationlab-3D8BD3)
![tag:hackathon](https://img.shields.io/badge/hackathon-5F43F1)

GENESIS lets an organization create a new recovery responsibility, recruit an
independent Fetch specialist to choose a replacement venue, verify the selection,
and ask its existing CREAO monitor to assess that replacement.

Send **help** to list the operator's public demo cases. Then send exactly
**recover CASE** to start that case, and **status CASE** to read progress. Replace
CASE with a listed name, for example `recover gala`. Use one text command per
message; no attachments, credentials, custom URLs or arbitrary instructions.

Each case contains a fixed, preapproved recovery request. Its accepted Reopen
assessment and verified candidate source jobs must already exist. A response may
require operator attention; chat cannot bypass a hold or renew evidence. A lost
response can be reconciled by repeating the same recovery command.

Completion reports the selected venue and its assessment evidence reference.
It is assessed feasibility, not a booking or completion of the entire mission.
The broader GENESIS vision includes two independent organizations sharing and
inheriting verified capabilities; this entry point currently exposes only the
bounded venue recovery subworkflow.

This template does not establish live provider execution, public registration,
or an ASI:One demonstration. Record and inspect those separately for the deployed
agent. Never present a fixture run as a live Apify or CREAO run.
